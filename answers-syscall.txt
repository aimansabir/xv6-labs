Looking at the backtrace output, which function called syscall?
Answer: usertrap (frame #1 in the gdb backtrace).
Q2: What is p->trapframe->a7 and what was its value?
A: It holds the user’s syscall number (RISC-V register a7). Here a7 = 0x0f (15 decimal) → SYS_open.
Q3: What was the previous CPU mode?
A: User mode (SPP = 0 from sstatus = 0x8000000200006022).
Q4: After forcing a null dereference, what happened?
A: Kernel panic with scause=0xd (load page fault), sepc=0x80001c7e, stval=0x0, because the kernel tried to read from address 0 (unmapped).
Q5: What instruction did the kernel panic at, and which register corresponds to ‘num’?
A: 80001c7e: 00002683    lw a3,0(zero). The destination register a3 corresponds to local variable ‘num’.
Q6: Which process was running when the kernel panicked?
A: name=init, pid=1.
